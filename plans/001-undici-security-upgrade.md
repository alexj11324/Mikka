## Why this matters

`undici` is pinned at `7.24.5`, which `pnpm audit` flags with ten high-severity advisories — including three TLS certificate-validation bypasses (SOCKS5 `ProxyAgent`, `BalancedPool`, and `Agent` dropping `tls` options) and cross-origin redirect cache poisoning with cross-user disclosure. The highest patched floor is `>=7.30.1`.

This matters more here than in a typical repo because `lib/plugins/public-fetch.ts` is **the sole egress path for plugins** — it constructs `Agent`/`ProxyAgent`/`undiciFetch` directly. That is exactly the proxy/redirect attack surface the advisories describe. A plugin that fetches through a SOCKS5 proxy can currently accept a MITM response it should reject.


**Verify**: prints `10` followed by ten advisory lines, the largest `patched_versions` being `>=7.30.1`.

### Step 2: Raise the pin

Use `7.30.1` exactly (the floor all ten advisories are patched at), not `^7.30.1` — the manifest pins exact versions for runtime deps.

**Verify**: `grep -n '"undici"' package.json` → `"undici": "7.30.1",`

**Verify**: `grep -A2 '^  undici@' pnpm-lock.yaml | head -5` shows `undici@7.30.1`. And `git diff --stat pnpm-lock.yaml` shows only undici-related resolution changes (no unrelated churn).
