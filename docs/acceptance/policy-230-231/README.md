# Organization policy backend candidate (#230 / #231)

This backend candidate is stacked on audit #259, source `9532817f3456ae0ed4decc9cd5d7e0e5bac95feb`; it does not change that branch. It contains no frontend design changes. Keep both issues open. No policy has been published in a real workspace, and no production authentication, permissions, migrations, credentials or deployment have been changed.

## Implemented behavior

`GET /api/policy?workspaceId=<uuid>[&version=N]` reads a signed publication and the current principal's effective layer explanation. Active workspace membership is required. `POST` accepts `{expectedVersion, document}` or `{expectedVersion, rollbackOf}`. Publication is restricted to current browser-session admins and the configured application's exact Origin. Worker/OAuth bearer credentials cannot publish. Requests are bounded to 64 KiB and unknown fields/schema versions are rejected.

A document has `schemaVersion:1`, state `enforce|revoked`, `offlineTtlSeconds:30..300`, and one workspace layer plus optional team/project/user layers. Lower defaults override higher defaults; accumulated ceilings always win. Same-level team/project defaults are applied in lexicographic id order. Network sets intersect conservatively (including empty lists); domains cannot reopen `network:allow`. Read-only propagates. Provider/model/endpoint/region tuples are exact, all applicable model ceilings must permit them, absent or empty admission is deny. `unknown` region explicitly makes no data residency promise. Only actual server-selected tuples are checked; user model aliases and proxy URLs cannot select routes.

PostgreSQL serializes publication with expected-version compare-and-swap. Every rollback is a new, higher version. Ed25519 signatures bind document hash, workspace and revision; the key derives from the existing auth secret with domain separation. Secret rotation therefore requires explicit republishing; there is no trust-on-first-use of arbitrary keys. Immutable version rows and a current-head lookup prevent old signed bytes from authorizing a later revision. This is application integrity, not protection from a privileged database owner rewriting all state.

Policy publication and audit append commit in the **same workspace transaction**. The #210 dependencies are `appendAudit(tx, tenant, AuditEvent)`, its transaction utility, and the read-only captured-scope projection `security_audit_resource_scopes(source, resource, tenant, owner_id)`; this candidate introduces no second audit store, export system or retention policy. Events contain references, hashes and fixed reason codes, never prompts, tokens or provider credentials. The new migration targets `DATABASE_URL`; it only creates policy tables and an immutability trigger.

Server guards cover ordinary Agent provider attempts, retries, Coordinator model steps and compaction, Decision calls, web-tool submodels, subscription/native broker authorization, normal claim, dedicated group-worker requests, worker MCP requests and generic lease renewal. Unscoped model requests intersect every active membership because the Coordinator currently mixes tenant context; selecting no workspace cannot drop policy. Issue-scoped worker requests use #210’s captured original tenant across retries, then derive current team/project from server tables; a conflicting later task move is refused. Revoked model/worker/tool denials are appended before returning the error. SDK transport refuses changed model ids, changed endpoints and redirects. Cancellation remains available.

## Explicit fail-closed dependencies

**Managed CLI/BYOS/child execution is refused** with `workerEnforcementUnavailable` or `toolEnforcementUnavailable`. Current CLIs cannot attest to all endpoints, descendants and geographic routes; their existing sandbox always exempts harness model endpoints. A claimed capability bit is insufficient. The candidate does not claim to propagate an enforceable policy hash through a supported managed CLI, verify daemon offline caches, or reuse an approval under a new policy.

**Managed model calls are refused** with `modelRouteDenied` (disallowed tuple), `policyRevoked`, or `policyBudgetUnavailable` (allowed tuple, #215 reservation adapter absent). No fallback sends the request. This lane must integrate #215's atomic pre-request reserve/settle/refund lifecycle with retry/timeout/cancellation semantics before enrolled model traffic is enabled. This candidate does not duplicate billing or claim budget enforcement based on mocks. No external model credential is used in isolated tests.

There is no policy cache in the server guard: DB/signature/current-version failures reject. `offlineTtlSeconds` is validated policy data for the future signed assignment handshake; it does not activate offline execution. Previously unregulated work in flight can finish its already-admitted request; new sensitive tool/model calls recheck, old worker tokens are denied, and daemon work stops on refused renewal or its existing 90-second lease expiry. Every persisted server-leased ordinary run now needs a fresh authenticated heartbeat before restart, including a still-unexpired journal lease and older remote assignments that omitted one. Offline, revoked, expired and missing-capability restarts stay blocked; repeated restarts cannot manufacture new local lease grace. The existing Skill source revalidation path remains mandatory for Skill runs and its server endpoint now checks centralized policy before renewing. Only explicitly configured local `--server memory` development runs retain their non-persistent fixture behavior; remote links still require revalidation even in dev flavor. This is not an emergency remote process kill guarantee. Runtime publication/admission across the application and workspace stores is not a distributed transaction; integration must retain this boundary and explicitly verify publication races before broader enablement.

## Validation and remaining acceptance

The explicit loopback `_e2e` PostgreSQL suite verifies concurrent publication, distinct tenant rules, role/origin restrictions, signatures, monotonic rollback, new-store restart reads, missing/replayed revision refusal, audit-failure rollback, suspension, immutable rows, aliases/endpoint/region denial and DB outage. `REQUIRE_POLICY_DB=1` fails if an isolated URL is missing. CI runs the actual tracked migrations twice and the protocol/daemon suites; DB checks cannot silently skip. The cloud Linux container and databases are dedicated to this candidate, with no production URL fallback.

Before enabling any real workspace: independent review, unified parent integration with #210/#207/#209, a frozen deployed Preview, real OAuth identity and isolated policy publication authorization, verified worker transport with signed effective-policy hash/TTL and approval binding, #215 budget adapter, real provider plus child/fallback requests, queued/in-flight/restart/concurrency/failure regression, and production rollout coordinated by the parent. Source/unit/CI/isolated API results are not production acceptance. No main merge is authorized here.

The first compiled-HTTP workflow attempt exposed a bad synthetic priority value and a shell pipeline that hid the script exit code. The fixture and pipeline are fixed; all pipelines use explicit Bash pipefail and API success also requires a complete passed receipt. Superseded green workflow status alone is not accepted as API evidence.

OAuth MCP review repair: every OAuth tool callback revalidates the opaque token after parsing, including client disable, token expiry/revocation and session expiry. Side-effect tools use server-captured workspace memberships and retain policy admission locks through the effect; removal/suspension during a delayed body cannot become an unmanaged call. The shared Composio boundary also admits before constructing its client. Local resource reads and `stop_run` retain their existing owner checks and fresh OAuth validation, and remain available after policy revocation. An account with no current enrolled workspace remains explicitly unmanaged; a fresh request after leaving all workspaces has personal semantics. No client-supplied workspace or owner field selects this state.

Coordinator SDK retries are disabled for both compaction and the WorkflowAgent. Durable retries must enter their policy gate again. The no-network SDK test uses real `ai@7.0.148` with a retryable 503 and proves one send, then rejects a new invocation after policy publication/revocation/version update. Real PG separately proves an admitted tool fences publication, later calls observe the new policy, and denied callbacks have zero effects. The original 15-test total comprised five contract cases, eight PG subtests, their parent and one SQL adapter case; it was not 15 PG scenarios. The existing six-call worker authorization regression concerns unmanaged run-token revocation, not policy version revocation. The new OAuth delayed-body regression supplies that separate policy evidence.

This candidate must be integrated with the reviewed #259 scope-inheritance repair (`1b39b709ce361b9643524aea983860e6de818ff6` or its reviewed successor). The original `9532817` audit base is unsafe for continuation runs moved across workspaces. Do not deploy this branch independently, and do not treat tests of the old audit base as coverage of its repaired integration. A parent-owned final combined SHA and cross-workspace continuation regression are required before release.

Missing captures, cycles and a personal/missing parent in a resume return `policyScopeUnverified`; a new run is required when the original organization cannot be independently verified. This intentionally also refuses legacy personal resumes whose history is ambiguous. An ordinary new unmanaged root retains the existing protocol; its personal projection cannot narrow admission to a selected unmanaged workspace when another current membership has an enrolled policy. These checks neither backfill historical scopes nor claim that the audit repair retroactively repairs them.
