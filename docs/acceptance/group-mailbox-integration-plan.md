Backend baseline: `efce5c812e06d20d86e993eb6554e6d91c3c4a3b`, based on main `5a0e1c411f487fee433c48414f7130d0d58dad92`.
Integration branch: `integrate/group-artifact-mailbox` in a separate cloud Linux worktree. Frontend remains paused and unchanged in the original worktree.

Source prerequisite: reviewed mailbox candidate `8cb80b11276b6314a6e15077b39506237790c305` from base `5a0e1c4`. Its Git object is currently absent. Internal source transfer is pending; no mailbox API names, behavior or compatibility are assumed in this plan. Do not implement a competing transport or adapt against an imagined interface.

## Existing concrete contracts

| Boundary | Current source | Required preservation |

Save comment alone creates no work. |
| Work → runtime input | `dispatchReviewWork(pool, directory, adapter, workId)` in `lib/group-review-runtime.ts` | Conversation lock, fresh authorization/grant/membership-epoch checks; `runId === workId`; atomic run/input/work transition. Repeated dispatch returns existing state without another enqueue. |
| Mailbox adapter seam | `runMessagesAdapter(prepare)` / `GroupRuntimeAdapter.enqueue(client, input)` | `prepare` uses supplied transaction client, no network. Insert dedicated queued `group_review` run with matching owner/Agent; no issue, repository, private session, prompt, prior messages or chunks. Existing run_messages insertion remains authoritative. |
| Delivery envelope | Existing `run_messages.text`, contract `mikka.group-review.v1` | Trusted binding fields and instruction are separate from `untrustedData.trigger`/`artifact` (original base content/hash/media type/anchor). Arbitrary content is not tools or trusted system instructions. |
| Runtime → review result | `completeReviewWork(pool, directory, adapter, authenticatedRunId, {workId, triggerMessageId, body, proposal?})` | Trusted run identity is supplied by runtime authentication, never browser/body author fields. Proposal binds original Artifact/base/hash. Late cancelled/revoked/stopped writes fail. One terminal reply/proposal per work. |
| Trusted HTTP reply | `POST /v1/runs/:runId/group-reply` | Existing device-owner authorization, dedicated run kind and strict payload schema. Browser session cannot authorize Agent authorship. Align with verified mailbox trust/claim mechanism rather than inventing credentials. |
| Same-conversation reads | Artifact `read` returns requests/work status; review `work` returns bound work; group messages return same conversation timeline | Pending/dispatched/completed/conflict/cancelled remain visible. ## Reconciliation decisions after source receipt

1. Verify all chunks, expected packet hash, base and target provenance before importing. Preserve original UI status and patch hash. Import reviewed source into the integration branch only; inspect overlapping files/migrations and resolve against backend contracts. If the transfer is a patch rather than original Git objects, report resulting commit identity separately from source provenance; do not claim the original SHA was reproduced.
2. Locate the mailbox candidate's actual independent-session creation, durable enqueue, claim, delivery acknowledgment, worker executor and completion interfaces. Map the existing `run_messages` seam to those interfaces; no second mailbox table or generic message bus. Identify the real scheduling entry point for pending `conversation_work` and its bounded batch/retry/recovery behavior.
3. Supply transactional run preparation. The current run_messages adapter rejects non-null sessionId because sessionId currently means private Agent session. If mailbox uses a different conversation-scoped session identity, reconcile that invariant explicitly: create a fresh group-only session, bind it in persisted records and enforce its scope at claim/delivery/reply. Do not simply remove the null guard or attach an existing private session.
4. Use a distinct claim/execution capability for `group_review`. Existing device claim requires repository/issue and may issue MCP worker tokens; bypassing that requirement alone is insufficient. Group execution must not receive private prompt/history, repository filesystem, owner environment, tool credentials, privileged tools or private memory. Verify actual candidate capability enforcement, not only an isolation sentence in its prompt. Harness identity may be selected from the authorized Agent without copying its private instructions/configuration wholesale.
5. Recheck work/grant/membership/stop before delivery, using current transaction lock order: conversation → work → run. Coordinate mailbox lease/delivery locks without reversing that order. Cancellation/revocation must prevent new delivery, discard undelivered input and stop only the dedicated group run. Regrant/rejoin must not revive old epochs. Workspace membership is checked through a separate DB; document its non-atomic propagation limit and recheck at dispatch/claim/delivery/completion.
6. Deliver typed reply/proposal through trusted completion before generic terminal-run handling. A terminal run without a review reply must not strand work forever or report success; choose an explicit recoverable/error outcome consistent with mailbox source. Do not pass group-review completion through repository verification/issue-review or private coordinator paths by accident. Persist retryable reply delivery so a crash after model output does not create a second revision or silently lose the reply.
7. A stale version before explicit send returns conflict. A base changed after queueing remains pinned to the original request; never retarget it silently. Current completion retains the proposed immutable candidate with `conflict` and does not advance head. Review whether mailbox can stop obsolete queued computation without losing visible conflict status; do not change semantics implicitly.

## Acceptance on disposable cloud Linux

Use real disposable Postgres for both app/workspace databases, actual additive migrations, replay and transaction/lock tests. Use fake provider/native worker and controlled identity fixtures only; no real model calls, E2B, credential creation, live email, production DB or publication. Keep frontend out of the integration worktree. Fixtures may inject an existing trusted-caller abstraction in the test process, but must not weaken production authentication or be described as a real device-login test.

1. Actual app handler persists a group human message/Artifact comment; saving alone leaves work count unchanged. Explicit send creates one trigger/request/work. Unauthorized workspace-only user, outsider, suspended/removed member, foreign Artifact/group reply/mention and foreign Agent grant are denied.
2. Invoke actual scheduling/dispatch entry point, not direct completion as a substitute. Assert exactly one durable run/input despite concurrent/repeated dispatch; rollback creates neither half-run nor half-message. Restart/replay recovers pending work without duplicate logical execution. Distinguish durable intent uniqueness from provider exactly-once guarantees.
3. Actual mailbox claim and worker dispatch consume the stored envelope with fake harness. Capture its real allowed context/capabilities. Seed private chats, Agent instructions, repository paths, tool settings and credential-shaped sentinels (not actual secrets); assert none are delivered. Other groups and workspaces remain absent. Do not launch a live provider binary.
4. Fake worker emits trusted reply plus version proposal through the actual completion plumbing. Assert one Agent-authored group reply linked to the trigger, original thread reply, immutable new version, same conversation and status. Acceptance remains unchanged until a human exact-version/hash action. Spoofed browser author/run/trigger/proposal bindings are rejected.
5. Exercise crash/retry after enqueue, claim, delivery and reply commit, duplicate completion and concurrent worker claims. Verify lease/ack behavior from actual source and ensure recovery neither duplicates revision/reply nor treats undelivered output as accepted.
6. Cancel/revoke/remove/suspend before dispatch, between dispatch and claim, during lease/delivery, and during completion. Use real lock waits where applicable. Late worker writes cannot revive cancelled work. Stopping one group run must not touch a private run; regrant does not revive an old intent. Automatic Agent reply chain remains zero.
7. Human advances Artifact head while work runs; worker submits proposal for original base. Assert visible conflict, unchanged winning head, retained immutable candidate and unchanged human acceptance. Stale/orphaned anchors cannot be sent and are never moved to another version.
8. Run affected app/protocol/worker types, lint, unit/integration tests and compare existing failures against exact source baselines. Record exact source/worker commits, commands and outcomes. Do not claim provider end-to-end or frontend/design acceptance.

The current 34 backend tests already cover core durable intent/reply/revision/authorization/stop semantics using a mocked adapter and real Postgres. They do not cover actual mailbox worker execution. That remaining boundary is the purpose of this integration.
