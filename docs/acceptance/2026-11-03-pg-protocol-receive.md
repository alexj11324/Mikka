# Connection-level PostgreSQL receive measurement

The existing 1% row-JSON sample cannot measure column descriptions, command/error messages and other PostgreSQL protocol traffic. Supplier egress remains unexplained; this change supplies evidence, not an asserted traffic reduction.

`db_transport_sample` reads each connected Node pg stream's cumulative `bytesRead`, once per runtime window (60 seconds) and at connection removal/close. Queued and overlapping queries do not get separate byte deltas. Default/request, workspace and authority-fence pools use the same collector. The production workspace DATABASE_URL was verified in memory to have the same normalized endpoint and database as MIKKA_DATABASE_URL; its historical Marketplace code comment does not reflect the current production scope. It never reads payloads or SQL/parameters, changes socket flow, or changes authority/transaction behavior. The existing `dbEgressSample` PostHog gate controls emission. Acquisition detects a gate loaded after connection creation, baselining there to exclude off-period data. Timers are unref'ed and stop when no tracked connections remain.

These are **received plaintext PostgreSQL protocol bytes from observed Node connections**, not HTTP bytes, estimated JSON, encrypted TLS bytes, or supplier metered bytes. Startup before registration is excluded. Go worker connections, other runtime instances and uninstrumented clients are outside a record's scope. Missing/reset/unavailable counters emit `coverage=incomplete` and `pgProtocolReceiveBytes=null`; the known partial contribution remains separate. Connection-close windows can be shorter than a minute. Runtime termination before final logging can lose a window; absent logs are never zero usage.

## Validation

- Three collector tests cover duplicate registration/acquisition, consecutive windows, remove+close idempotence, gate off→on→off→on exclusion, and unavailable/decreasing counters.
- Twelve related collector/JSON-sampling/request-scope/device error tests passed; all 73 library unit tests, root typecheck and root oxlint passed. All five real isolated device-unit-fence tests passed, including revocation ordering, idle burst release, hung-fence refusal, pool exhaustion and concurrent requests; the same five tests also passed with the egress gate enabled through the test-only switch override.
- Real isolated PostgreSQL `mikka_transport_e2e` on loopback: 80 queued synthetic SELECTs on two connections across separate request/workspace pools (alternating a boolean and a 22-column empty result), one database identity read and one error response produced **36,831 PG protocol bytes**, versus **600 row-JSON bytes** for the 80 synthetic results. The measured aggregate equalled both socket-counter deltas exactly and did not change after remove/close settlement. A second real-PG case imports the actual workspace-db runtime, captures its workspace-scoped close record and verifies nonzero protocol bytes. No production records or message contents were used.
- Red/green: deliberately disabling counter accumulation makes the real database exact-byte assertion fail; restoring it passes. The real PG test is included in existing `test:ops-db` CI suites; unit tests are in `test:lib-units`.
- This synthetic example demonstrates a blind spot; it does not establish the production overhead share or explain the supplier's full hourly traffic.

## Corrected fence performance measurement

The first CI run for head `3691b502` failed the existing device-fence performance assertion: whole-database `pg_stat_database` totals reported 11 versus 6 transactions. The downstream production-build job refused its prerequisite gate before compilation; this was not a compilation failure.

That old assertion read asynchronous cumulative counters, included its own admin queries, and used a fixed 1.2-second sleep. PostgreSQL17 [statistics documentation](https://www.postgresql.org/docs/17/monitoring-stats.html#MONITORING-STATS-VIEWS) explains that each backend flushes counters asynchronously; `pg_stat_clear_snapshot()` invalidates the reader snapshot and does not flush other backends. Whole-database deltas cannot isolate one request this way.

The test now observes actual PostgreSQL `CommandComplete(BEGIN)` and `ReadyForQuery` events from clients checked out by the tested process, over one awaited queued-runs GET. It retains all concurrency, revocation, hung-fence and exhausted-pool assertions. Measured per-statement→unit-fence values are **explicit authorization transactions2→1**, **PG round trips11→6**, and **total completed transactions3→4**. The unit fence adds a separate authority transaction and allows business reads to autocommit; it does not reduce total transactions in this fixture. The assertion now checks the actual reduction in authorization transactions and round trips, without changing production authority behavior or relaxing a numeric threshold.

A controlled regression that runs per-statement authorization on both sides fails the explicit-transaction assertion; restoring the unit mode passes. These counts describe the isolated fixture and do not establish production billing savings.
