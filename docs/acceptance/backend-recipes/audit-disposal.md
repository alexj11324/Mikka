# Audit disposal: prepare, review, then resume

The default R0 recipe stays pending. `AUDIT_DELETION_ACCEPTANCE_AUTHORIZED=1` no longer enables it.

1. Allocate a new run ID (`r0-disposal-<UUID>`) and four distinct UUIDs in a private plan file (mode 0600): `tenant`, `agedTenant`, `eventId`, `agedEventId`. Set `owner` to `audit_pending_<runId>`.
2. Provision a **new, empty, loopback-only** database named `mikka_audit_disposal_<run UUID without hyphens>_e2e`, with the audit core schema. Do not replay the full application migration on an existing/shared database: it contains trigger replacement statements. Retain the container and database. No credentials from production are needed.
3. Run `node --import tsx scripts/prepare-audit-disposal.ts PLAN NEW_MANIFEST`, supplying the explicit `AUDIT_APP_TEST_URL`. Setup inserts two audit events and an ownership row, writes the exact environment/source/row snapshot and exits. It never imports the deletion test. It refuses nonempty audit fixtures and will not overwrite a manifest. If writing evidence fails after commit, preserve the database and investigate; do not retry cleanup.
4. Review the private manifest and actual resources. **Stop here for separate, explicit one-run deletion approval.** Do not generate an approval from an environment flag. The approval issuer must attest the exact manifest bytes (`manifestHash`, SHA256), `sourceHash`, `runId`, `decision: approve-one-audit-disposal-run`, `maxPersistentDeletedEvents: 1`, a real `authorizationReference`, and `expiresAt` within one hour. The file must be private and task-owned. The file records an externally obtained approval; it does not establish consent by itself.
5. Only after that approval, supply `AUDIT_DISPOSAL_MANIFEST` and `AUDIT_DISPOSAL_APPROVAL` to the existing pending test command. The harness checks the files before connecting, then checks server system ID/database OID/schema, complete audit snapshots and the owner record. It consumes the one-run receipt before the test, keeps a session lock and uses one pinned connection without reconnecting. Crash/failure leaves the receipt consumed; no automatic retry. The actual prune locks the event table and requires exactly the approved aged event before calling the existing prune implementation.

The resumed test retains its original deletion-refusal/corruption rollback, legal-hold/export-lease, prune and tombstone assertions. It deletes at most one aged event persistently. All remaining rows, database, container and evidence remain retained. Shared or concurrent privileged use of this dedicated database is outside the contract and must not occur.

Source-only checks: `node --import tsx --test lib/audit/disposal-contract.test.ts`; R0 inventory: `node --test scripts/run-db-tests.test.mjs`. Neither command connects to a database or performs deletion. A missing-approval invocation must reject before entering the test body. Do not run the positive disposal path to test the gate.
