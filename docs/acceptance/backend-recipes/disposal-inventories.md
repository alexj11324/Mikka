# Retained resource inventories

These helpers collect evidence; none grants deletion permission. The five physical-disposal recipes remain pending.

- `scripts/disposal/byos-inventory.mjs` reproduces the worker's actual OAuth-attempt cleanup join, enumerates exact stateHash PKs and artifact associations, and rejects cross-scope aliases, duplicates or budget overflow. It is not yet a pause hook in Worker.Cleanup.
- `scripts/disposal/factory-effects.mjs` reads PostgreSQL PK/FK metadata in a read-only repeatable-read transaction. It models each existing Factory harness schema, composite keys, cascades and leaf SET NULL effects. Every reachable row must already be registered in setup; external schemas, unknown references, unsupported update effects and budget overflow refuse. It returns hashes, not row bodies. Original Factory test deletion sites still require prepare/resume wiring.
- `test:disposal-catalog-db` verifies those queries against real PG with newly created minimal synthetic schemas/rows. It checks catalog array parsing, composite cascades, SET NULL and a hostile BYOS alias. No DELETE/DROP is issued. This is catalog/join acceptance, not original Factory/BYOS disposal acceptance.
- `lib/credentials/acceptance-resource-registry.ts` reserves explicit launch/profile budgets and records exact private profile realpath/device/inode plus process PID/starttime/UID. Identity matches are observations, not permission to signal a PID or remove a path. The product's private Chromium lifecycle currently has no test hook; reliable creation-before-budget and disposal-time enforcement need the original owner's lifecycle boundary and a stable process handle. No global monkeypatch or production permission change is used.

Pure inventory tests and the retained PG catalog recipe are separate CI entries. Their success must not turn a pending physical-disposal recipe green or reuse any previous one-run container approval.

Native harness registration now reserves at most 30 create attempts and 9 runtime-config allocations before creation, and binds Docker operations to full container IDs with run labels and immutable identity checks. Its 11 pure tests use mocks for Docker; no new native run or disposal was executed. The original `--rm` behavior is preserved, so the native recipe remains pending approval. Runtime-config identity is checked at Docker boundaries, but product `dispose()` has no registry callback immediately before removing its directory. `dataDir` and `blockRm` cleanup are also outside this registry. These paths are not claimed as disposal-time identity enforcement and must stay pending until their lifecycle owner supplies that boundary.

The FK helper now refuses any enabled user trigger or rule in the fixture schema. Real Factory migrations include credential-lifecycle and audit triggers, so their side effects must be explicitly modeled before original-harness setup/resume can be accepted. NO ACTION/DEFERRABLE cycles are also conservatively refused; the minimal catalog regression does not prove the full Factory migration graph. It installs inert synthetic trigger/rule metadata and checks refusal without executing deletion.

The next retained wiring phase adds a private BYOS Cleanup observer before any mutation or external Delete; it always pauses, even when the observer succeeds. Its read-only snapshot lists exact artifact/attempt candidates and refuses foreign ownership or budget overflow. Enrollment effects remain incomplete. Four new Go tests are registered in the retained contract and require real PG CI confirmation.

Factory's first original physical-absence case now has an actual setup-only branch before its ordinary regression cases. A fresh-schema-only bootstrap pins all 67 source migration bytes and applies finite exact conversions instead of executing DROP statements. The resulting PG17 schema-only dump matches a retained original migration reference after namespace and pg_dump noise normalization (ownership, privileges, data and the migration ledger are excluded). The original migration gate and SQL files are unchanged. Setup records every fixture PK and hashes user trigger/function definitions; unmodeled effects still make the receipt blocked and ineligible for approval.

Native runtime config allocation/disposal now uses the registry lifecycle hook through the daemon. Retained mode verifies directory identity and returns before removal; dataDir and blockRm artifacts are retained. Container auto-removal remains outside that authorization and the native recipe stays pending.

Credentials acceptance now stops before calling Playwright launch. The executor's actual open path prepares and registers a private profile, records launch-blocked, and exhausts its one-use budget without starting a child. Playwright itself owns launch-failure/host-exit cleanup, so the previous observer alone could not guarantee retention; successful-process hooks do not authorize a new browser launch. Default product behavior is unchanged. Real browser/process disposal acceptance remains pending a separately bounded execution contract.
