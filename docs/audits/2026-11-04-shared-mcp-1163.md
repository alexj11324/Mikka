# Explicit workspace sharing for custom MCP (#1163)

The existing Composio app path remains personal to the requester. This follow-up
extends the existing custom MCP connection store with an explicit owner grant to
one existing team workspace. It does not introduce a second workspace permission
system, enterprise identity, a new provider connection, or an implicit loan of a
Bot owner's resources.

## Authority and lifecycle

- `GET /api/integrations/mcp?workspaceId=<uuid>` lists the person's connections
  and enabled connections explicitly shared into that workspace by active members.
  The existing GET without a workspace keeps its personal-only response.
- `PATCH /api/integrations/mcp/shares` accepts only
  `{serverId,workspaceId,shared}`. It requires a normal fresh owner session,
  same-origin request and active membership in the team. An admin cannot share
  another person's connection. Agent tools cannot grant or revoke access.
- The share table binds a UUID to a connection and workspace. Repeating the same
  share preserves that UUID. Revoking and sharing again creates a new UUID, so a
  previous execution's authority never returns by accident. The normal member
  departure path removes that owner's shares.
- New Coordinator execution snapshots contain requester, workspace, server owner,
  server revision and exact grant UUID. They contain no endpoint, credential or
  resource owner's private instructions. A delegated worker inherits only the
  host-frozen parent refs; retries and device rebinds preserve them. Legacy
  snapshots and run tokens acquire no new shared capability.
- Connection discovery/call rechecks enabled state, revision, grant and both
  memberships before connecting and after MCP initialization. The worker path
  also rechecks the same run token, lease and frozen execution identity. Claim
  and renewal use the existing identity enforcement. A withdrawn resource cannot
  be replaced with a different member's connection or a new grant.
- Native workers use the existing app MCP transport (`custom_mcp`). The daemon
  receives only its run token. All third-party credentials remain on the host.
  Tool results, discovery output and diagnostics are masked against the actual
  connection's secret values and private endpoint, including another owner's
  credentials. Uncertain external tool outcomes retain the existing no-retry rule.
- Run and Artifact `resourceBindings` retain the trusted MCP owner, workspace,
  connection revision and grant reference. They describe resource authorization;
  they do not assert that an external provider charged a particular dollar amount.
  Output ownership remains the requester. Historical records are not rewritten
  when a share or membership is withdrawn.
