## Shared Coordinator prompt versus selected quota workspace

The authenticated message endpoint captures B, but preparePrompt/loadConversation still load user-wide history, summary and memory. The old adapter applied only B's policy. The actual pre-fix compiled Next/Workflow SDK reproduction sends three synthetic A markers with both managed and unmanaged B, despite A denying that route. It does not claim a8533de was the locally compiled artifact. Only synthetic fixture markers are used, and output records boolean observations rather than prompt bodies.

The private model-admission helper now keeps captured B membership and quota/source fences, separately intersects policies across the person's retained active memberships, and holds deterministic membership/policy locks through provider work. A retained suspended membership with a managed policy refuses shared-context model work, so suspension cannot remove a policy while summary/memory remain. Even an unmanaged retained workspace's initial policy publication is serialized by its advisory lock. Denials are audited against the constraining policy workspace. No public positive policy API, default legacy gate or worker/tool policy is relaxed.

Both availability and actual execution use this helper, including compaction and decision resources. Scheduled reads retain their explicit task/workspace scope because scheduledAgent does not load the global Coordinator conversation; they still use the existing B quota and domain source fence. The change does not partition history or silently clear summary/memory. Authorized shared-context calls still receive their global context and charge only captured B.

Supported workspace removal currently updates membership status to suspended. Physical deletion of a membership row is not exposed by the current workspace action. Existing legacy summary/memory lack complete provenance, so this correction does not claim to reconstruct dependencies after arbitrary physical membership deletion or historical team/project removal. Such lifecycle changes require retained provenance/reconciliation before treating old global context as partitioned. The independent read-only reviewer found no demonstrated reachable residual bypass in the supported suspension path and no new lock cycle; this lifecycle limit remains explicit for R.

## Provider rejection versus local commit denial

The old catch path called quotaFailure on any post-send error. A local 403 from usage/commit after a provider's HTTP200 was consequently refunded. The new path records explicit non-2xx HTTP response evidence inside the guarded transport. Only a proven first provider 401/402/403/429 can refund sent work. Successful HTTP followed by decoding, local 403, a wrapped status, usage failure or PostgreSQL/domain-commit failure retains full uncertain units (or an already committed immutable settlement). The denied receipt/publication stays rolled back and retry cannot resend unknown work. Proven unsent work still refunds. The generic quota classifier and other runtimes are unchanged.
