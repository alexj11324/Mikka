`ResourceModelExecution.available(scope, route)` inspects existing allocation/configuration without reserving or spending rate. `run(scope, route, invoke, {fence, signal?, timeoutMs?, leaseMs?, usage?, commit?})` reserves/activates the canonical ledger, revalidates source/quota immediately before fetch, bounds response-body reading and finishes its outcome. Defaults are 40s total transport/body deadline and 60s reservation lease, under the outer 45s, zero-retry generation boundary. Database acquisition/cleanup can outlast the transport deadline; no new provider send can occur after it expires.

`runTool(scope, invoke, {preflight, fence, ...})` shares that implementation and uses the existing `PolicyStore.withTool` gate. Its callback receives the already held workspace client; existing callbacks that accept no arguments remain compatible. Managed tool execution without its certified private executor is still denied. Search cache hits and successful domain receipt replays are authorized before access and consume no new provider reservation. The provider transport is fixed to hosted Firecrawl endpoints, never the user-supplied page URL. Markdown delivered to the tool is capped at 12,000 characters, URLs at 2,048; provider DNS/redirect/body validation is retained.

`ModelSource` is captured from persisted event/occurrence state, never accepted from user JSON. Coordinator scope contains owner/workspace/event/replay-generation/holder/delivery; schedule scope additionally contains occurrence/schedule/version/lease. The actual send requires current membership, the exact captured tenant and current generation/lease. `QuotaWorkflowModel(source, modelId, resource?)` uses the real installed AI Workflow `doGenerateStep` and its stable step metadata. Both human Bot transports capture workspace: authenticated HTTP and `sendCoordinatorMessage` server action. Ambiguous or inaccessible workspace selection is rejected; no membership is created.

Canonical quota additions preserve prior callers: `inspect`, an optional transactional source fence on `revalidate`, an optional domain commit callback on `finish`, and `beginQuotaWith` for the existing reservation activation path. A quota reservation is never a model result cache. First explicit 401/402/403/429 can refund that request; unknown sent outcomes retain the full uncertain amount and cannot resend under the same operation key. A later failed step never refunds previous successful work.

The scheduled backend's existing read-only executor receives `scheduledAgent.read(ownerId, task, operationId, source)`. This is the existing scheduled task executor, not a restored standalone conversation runtime. The result is checkpointed separately from original-chat publication. Publication rollback reuses the immutable result; a lost result checkpoint or an old unknown in-flight model attempt becomes uncertain and cannot regenerate. External write schedules are still unsupported; #207/#208 approval interfaces are not bypassed.
