# Personal message provenance, independent batch

Base: `8008d9468acbacf20beced57cfd046f7320d13fa` (main's personal run control/submission fix). This batch extracts only personal message provenance/prompt safety from the preserved #287 candidates. It adds no schema, database migration, feature flag, tool, mailbox storage, AgentKit registration, subscription/model selection, organization policy or UI. The older full #287 is not a dependency.

The existing MCP `send_to_coordinator` producer records a `run_report` with result tier, preserving wake-on-send while distinguishing Agent prose from authenticated human chat. `takeInbox` stamps source event ID/time and non-user classification from the server event record. JSON or role/delimiter claims inside the text cannot choose this metadata. Real `user_message` events remain direct input. Existing unknown history is not backfilled as human authority: prior MCP messages and real user messages were indistinguishable in that storage, so legacy entries remain unattributed coordination data until original evidence or a fresh human request establishes permission.

`promptMessages` projects non-user events as escaped, versioned data packets; their raw stored projection remains available to the existing chat. Both actual SDK `preparePrompt` and native enqueue consume this projection. Current fixed policy is included in Coordinator/native/daemon run instructions and creates no tools. `[Event]` and `[Handoff]` text are display markers, not source authentication. Reports, external notifications, prior assistant statements and summaries cannot establish new human permission. ACK/delivery/execution are distinct. This is provenance and prompt defense; it cannot guarantee that a model never makes a semantic mistake or replace host-enforced authorization.

Compaction retains a host-generated source ledger, observed pending state and the newest stamped human record separately from untrusted model summary prose. The existing `BETTER_AUTH_SECRET` signs the summary payload with owner/private-Bot scope; no new credential or persisted permission is created. The secret must already be at least32 characters before model compaction; missing/short keys fail before that model call. Invalid signatures, another owner's/Bot's scope, key rotation or a legacy summary produce an explicitly unverified projection, never original human approval. Only32 recent references are projected with exact omission counts, including pending/unverified omissions; the complete ledger remains in the existing summary field. No ledger or signature authorizes an action. Native's existing500k context limit and lack of automatic native compaction remain unchanged.

Existing `send_to_run` tools classify forwarded text as peer data at trusted server call sites. `sendOwnedRunMessage` keeps main's same owner predicate, `FOR UPDATE`, live-status and STOP recheck in its transaction; the new envelope uses the actual inserted message ID. App human actions retain raw user text by default. Tool/user JSON cannot choose the separate origin argument. This changes neither tool access nor run-control permissions. Existing CC/Codex daemon adapters consume the common `RunContext` policy; no hosted/native executor fields or BYOS selection are changed.
