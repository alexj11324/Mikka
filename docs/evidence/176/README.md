# Isolated durable Coordinator consumption acceptance

This is public-core backend work for #176, stacked on #271 (`b7d7358a90cee9fde8e6c311159ce34b585c7374`) and #269. Those reviewed heads are unchanged. Runtime source is frozen at `1b8a18e0b7284fee286cd53d27d939532fcdc6fd`; the later evidence commit changes documentation and the mailbox migration-order regression fixture only; runtime code is unchanged. No production migration, deployment, cron registration, IAM change, external message, paid model call or cloud Workflow run was performed. Issues remain open.

## Formal code

The existing `coordinator_events` inbox, `coordinator_sessions` lease, `coordinator_messages` history, Workflow entry and `/api/cron/runtime` compensation entry remain the only product pipeline. There is no second product scheduler, queue or outbox. `retryInboxWakes` now recovers staged but unacknowledged events as well as transport failures. A transport start ACK does not mark an event processed.

The event ID is the stable logical operation ID. A delivery token and current session holder fence staging, tools, checkpoints and publication. Input/output message IDs are deterministic. A separate PostgreSQL checkpoint commits the returned result before the publication transaction; publication and `processed_at`/batch closure commit together. Retry after publication failure reuses that immutable checkpoint. The complete transaction already atomically commits run status, token revocation and result/lifecycle events; it is reused rather than rewritten. An insert trigger captures its server-owned mailbox scope and makes the lifecycle event background when the peer result already wakes the same completion.

Defaults are five attempts per replay generation, 30-second exponential backoff capped at 15 minutes, a 60-second delivery reservation and ten-minute consumer lease. Tests explicitly use a one-second lease and short backoff. Exhaustion is durable and visible in the existing conversation error plus owner-authenticated `GET /api/coordinator/events/:eventId/wake`. `POST` replay requires fresh session/origin checks, current authority, expected generation and a terminal retryable failure. It preserves the logical operation ID. It is not a permission grant. Unknown generation outcomes and ambiguous legacy delivered events require reconciliation and cannot be blindly replayed.

Current user, workspace membership, issue/run/device ownership and stop state are rechecked. Workspace locks precede app transactions; resource admission runs outside those transactions. A stopped run cannot start generation or tools; recovery publishes a deterministic stop notice. Already staged background children are fenced and acknowledged with their parent, while a stop notice does not take fresh background work. On recovery the Agent receives read tools and existing persisted Calendar slots, not a new grant to invent mutations. A source-scoped schedule tool now uses its authenticated event's persisted workspace even when the owner belongs to several workspaces.

The installed SDK's model retry default is explicitly overridden with zero retries. Historical compaction also has zero model and step retries. Model calls have 45-second timeouts. A send-boundary failure with no checkpoint is conservatively `uncertain`: this is not proof that a provider received or charged a request. Provider-specific reconciliation/admission remains necessary before enabling paid execution.

## Evidence and limits

The final `postgres.log`/`.cast` print their exact source SHA and run the formal PG store and actual Coordinator schedule handler. Older SHA recordings and initial failed/diagnostic logs are retained and are not presented as final-source acceptance. The public `http-first-diagnostic.log` is a sanitized copy: 13 expired synthetic delivery-fence fields (including eight flagged occurrences) were redacted after GitGuardian detected them. No history rewrite or detector suppression was used. `gitguardian-classification.json` records a bounded diagnostic mapping for six incident IDs behind eight flagged occurrences, expired fixture leases and matching credential-table counts. This is not an independent secret clearance: the scanner failure remains unresolved, while the user reports prior false positives and directs no further separate email/dashboard investigation. No safety gate or required-check setting is changed.

The fixed source builds in cloud Linux using the real Next compiler. The standalone build reuses byte-identical native worker binaries from frozen #269 (unchanged worker source); remote CI independently runs the full pinned worker build. The known Serde warning about SDK classes importing Node built-ins also appears in #269's retained build logs; a green build does not establish cloud Workflow runtime acceptance.

Receipt/checkpoint/dedupe data is not automatically pruned. This patch does not delete data or create a new retention job. Retention must preserve the logical operation and processed tombstone together with its source conversation; any deletion policy requires separately authorized lifecycle work.

## Reproduction

Use isolated loopback PostgreSQL databases with names ending `_176`, no cloud/model credentials, Node 24 and pnpm 10.34.3. Apply all tracked migrations with both database targets directed to that disposable instance. Run `pnpm test:wake`, `pnpm test:wake:postgres`, the existing schedule/approved-action suites, type/lint/check and the full build. For HTTP acceptance, launch the built Next service on `127.0.0.1:3176` with `CI=true`, the existing runtime sweep enabled, synthetic auth/cron values, and the guarded controlled transport origin `http://127.0.0.1:6176`. Run `scripts/verify-wake-http.mjs` with its synthetic-only environment. It starts/kills the transport and restarts only the container named `mikka176-next`.

The concrete remaining boundary is an approved, composed runtime with a resource admission adapter and real Workflow/model/harness transport. `WorkflowAgent.generate` and `scheduledAgent.read` provider acceptance was not attempted because real provider consumption is outside this delegation. The scheduled read model remains default-off; its quota/revalidation and generated-result checkpoint composition must be validated before enabling it. No private enterprise adapter is published here. Production migration/release and the common minute relay activation remain for the parent's unified approval and execution. Neither #176 nor #179 is closed.
