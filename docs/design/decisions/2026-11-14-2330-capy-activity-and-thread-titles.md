# 任务活动照 Capy 写；给对话起名，不给任务起名

Alex，2026-11-14。

## 决定

文案和交互照 Capy 0.8.0 的任务（issue）页做，Mikka 自己另起的做法删掉。

**活动**

- 一件事一行，不再把同一分钟的几件事合成一行。每行是事件图标、一句话、`·`、相对时间，悬停看具体时间。
- 句子以「谁」开头：人写名字；Agent 写它所在的那段对话（芯片，显示对话标题，点开进对话）；没有操作者写 Mikka。不写 Claude Code、Codex 这类 Agent 名。
- 英文逐字照 Capy 的句子，issue 换成 task；中文直译。事件种类照 Capy：创建、移到某状态、设优先级、改名、编辑描述、指派 / 取消指派、设置 / 移除父任务、添加子任务、标记被阻塞 / 相关、移除关系、关联 / 取消关联 PR；合并 PR 单独一行，不带操作者。标签不是活动事件。
- 任务编号、对话、PR 是芯片，悬停显示 Capy 的卡片：任务卡是状态、编号、状态名、优先级、标题、负责人；对话卡是 Agent、对话标题、运行结果和时间。
- 标题行是「活动」和「全部 / 评论 / Agent 和 Bot」；关注只在 ⋯ 菜单。最近 50 行，上面是「显示更早的 n 条」。
- 评论是一张卡，回复在卡内；悬停出现复制、回复；点回复才在卡底打开「回复 某人」。没有「解决」。

**描述**

- 「描述 ⌄」可折叠，悬停出现铅笔，空描述显示「暂无描述」，编辑占位「描述这个任务」。描述仍是多人实时协同、自动保存（Linear 也是），所以没有 Capy 的 Save / Cancel，也没有「完成」。

**属性**

- 属性从右侧卡片挪到标题下面，一列：图标和标签，然后是值，可改的值带 ▾，照 Capy 的顺序（父任务、状态、优先级、截止日期、负责人、标签、创建者、PR、线程、关联任务）。没设的属性不显示，从 ⋯ 菜单设置（团队也加进了 ⋯ 菜单）；工作区不显示（R-79）。标题下面一行是「编号 · 多久前」。
- 文案照 Capy：「PR」（英文按数量 Pull request / Pull requests）、「对话」（Thread / Threads）、「无负责人」（No assignee）、「创建者」（Created by）、「+ 关联 PR」（Link pull request）。
- **付费组件例外（Alex 批准，2026-11-14）**：任务页不再用 affectUI 看板 IssueDetail 的属性卡，属性列是 Mikka 自己写的，照 Capy 的排版。

**工作**

- 删掉描述下的「工作」区（取代 [2026-11-13-1912](2026-11-13-1912-task-work-and-activity.md) 的「任务详情在描述之后显示工作」）。任务页只说到哪了、要不要你：属性里「对话」「关联 PR」每项一行，对话写它的 Factory 阶段或运行结果，PR 写标题和实时状态，下面是「+ 关联 PR」，照 Capy 的 Thread / Pull requests 行。
- Factory 的进度说明是 Bot 每个阶段在任务里发的一条评论（2026-11-04-2200「一个声音」），出现在活动里；运行的步骤在对话里看；验收报告是 Artifact。

**标题**

- Capy 用小模型给对话（thread）起名，从不生成任务标题。#1477 的任务短标题（[2026-11-06-1400](2026-11-06-1400-task-short-titles.md)）是转述时的误读，这里删掉：列表显示任务自己的标题，库里的旧列暂留，删列另做迁移。
- 对话标题沿用 #2262 / #2364 的实现（`agent_runs.title`），并补上 Capy 的「Thread titles」设置：工作区和个人的标题说明（个人的叠加在工作区之上），以及何时重新生成标题（第一条消息完成 / 打开 PR / 任一，个人可选「工作区默认」）。手动设置的标题保留。

### 审查和验证是子对话（Alex，2026-11-15）

- 审查、验证照样独立运行（自己的 run、自己的 Agent），但不再是任务的顶层对话：任务页「对话」属性只列 `implement` / `plan` 的对话。
- 它在所检查的对话里显示为 affectUI Thread 自带的任务卡片（`ThreadTask`，原样使用，只换数据：标题、运行结果），放在它开始的时间点（`lib/thread-child-entries.ts`）。「打开」进入它自己的对话，← 回到所检查的对话。
- 审查页（bare）和不能回复的对话仍把每个 run 内联，不画卡片。

### 对话里的派出和状态（2026-11-15）

- 派出时的指令是对话的第一条消息，作者是派出它的 Bot（Bot 的头像和名字）；没有 Bot 派出时（审查、验证）作者是 Mikka。不再显示「X 派出了这个任务」的灰字。
- 阶段分隔线只在对话中途换阶段时出现，第一段上方不画。
- 子对话的任务卡片挂在 Mikka 名下；状态行在没有 Bot 时不再把 Agent 名当成派出者。
- 子线程（审查、验证）不能回复，所以没有输入框（Alex，2026-11-15，付费 Thread 的批准例外）。
- 照 Capy 的线程页（Alex 2026-11-15 批准付费 Thread 的三处例外）：Agent 的回复不再有「Claude Code 23:24」作者行，只有正文；运行状态改成居中的一条活动线（「工作了 2 分 3 秒」「正在工作 · 12 秒」「在等你回复」），取代「完成 · 开始于 … · Agent」；工具组按做了什么命名（「读了 3 个文件，跑了 2 条命令」）。
- 同日补齐 Capy 的另外三处：子线程第一条消息的派出者名字可以点，回到父线程；做完的运行把步骤折在活动线下，点活动线展开；任务页里线程顶部不再留出模板标题栏的空白。
- 子线程在父线程里是它的汇报：有总结就先写总结，再跟它的任务卡片（标题、结果、打开），不另起作者行。子线程只读。

### Artifact 按 Warp 放在线程里（Alex，2026-11-15）

- 照 Warp 运行页右侧的 Artifacts 标签（Plans / PRs / Screencaptures，各带数量）：线程有产出时，标签行多一个「Artifact」，与「线程 / 改动 / 验收」同一行（形状见下一节）。分组依次是方案、PR、报告、截图和录屏，各带数量，空组不显示。工单、方案和 PR 都是 Artifact。
- 任务的对话显示整个 Factory 任务的产出（任务的工作读取，不另发请求）；审查、验证子线程只显示自己运行的产出；没有 Factory 任务的线程读它自己运行的证据（`/api/runs/:runId/evidence`）。方案和报告用 Artifact 阅读器打开，PR 打开 GitHub，截图和录屏用原来的证据查看器。
- 线程顶部的 Artifact 按钮打开这个标签；完成消息下的 Artifact 卡片保留（2026-11-06 的决定）。
- 任务页没有证据清单：删掉 `FactoryEvidence`。旧的证据链接（`?issue=…&factoryTask=…&evidence=…`，iOS「在网页打开」和 Bot 评论）打开产出它的运行所在的线程，切到 Artifact 并定位到那一项；读不到的回执停在任务页，不报 404。

### 线程 | Artifact 切换，照 ChatGPT 聊天 | 工作（Alex，2026-11-15）

- 线程顶部一个毛玻璃分段控件「线程 | Artifact」，照 ChatGPT iOS 顶栏的「聊天 | 工作」：选中的一段是稍深的内层胶囊。iOS 放在导航栏正中；网页放在线程标题那一行的右上角、⋯ 旁边（Alex 2026-11-15），取代原来的标签行，有「改动」「验收」时也在同一个控件里；它是 Mikka 自己的 UI（语义色、背景模糊、半透明底、细边框），不是付费组件。顶栏的 Artifact 按钮、键盘和标签语义、`?evidence=` 深链（打开 Artifact）照旧。
- iOS 的线程页（无任务的线程和任务的线程）在顶栏正中放系统分段控件（iOS 26 是 Liquid Glass），浮在内容上，左边仍是返回。线程没有 Artifact 时不显示控件，顶栏照旧显示标题。Artifact 一段按方案、PR、报告、截图和录屏分组：PR 打开 GitHub，方案和报告用 Artifact 阅读器（HTML 在网页打开），截图用图片查看器，录屏在网页打开。
- 手机的读取是 `GET /api/mobile/threads/:id/artifacts`（`lib/mobile-thread-artifacts.ts`），和网页同源同权限：只读本人的线程，所选工作区之外读不到；任务的线程读任务的工作（任务内容权限再查一次），审查、验证子线程只读自己的运行，没有 Factory 任务的线程读自己运行的证据。
- 同日：中文界面不再用「对话」一词，线程、Bot 的聊天、目录和新建入口都叫「线程」，群聊仍叫「群聊」，只有「对话框」保留（`pnpm i18n:check` 拦截）。

### iOS 任务页（Alex 批准，2026-11-15）

- iOS 任务页照网页：标题下一列属性（父任务、状态、优先级、负责人或「无负责人」、创建者、PR、对话、其他关联任务），没设的不显示；不再有状态词、Bot、Agent、位置的芯片。
- 对话行只列任务自己的对话，每行是状态标记、标题（无标题写「无标题线程」）和阶段或结果；PR 行是状态颜色的 PR 标记、安静的 `repo#n` 和标题，不写状态词。
- 活动一件事一行，句子和网页同一套（`activityLineParts`），后面是相对时间；没有 Factory 证据行。

## 没做

- 对话里的 Factory 阶段标记（Web / 桌面）。对话读到的运行数据还没有阶段，要先补数据；iOS 已有「修改」标记和审阅卡。

- 对话编号（Capy 的 `FRO-12`）：不做（Alex，2026-11-15）。和 Cursor 一样，对话只用自动生成的标题。
- 评论的「已编辑」：讨论消息没有编辑时间。
- 未读「New」分隔线、评论附件和 @、可见性变化事件。
