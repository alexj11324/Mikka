# PR 面：列表、详情与一次量好的工艺基线

2026-11-18。Alex 的原话：「Look at this PR interface, it is completely messed up, very messy, very ugly.」他同时要求以 Capy 桌面版 0.9.2 为参照（「capy 怎么做，你就怎么做」的同一条思路），并让这件事在本地机器上做。

PR 面是官方界面里唯一没有搬进官方组件集的一页：外壳、看板、任务、线程、审阅页都由 `mikka-hosted-ui` 的槽渲染，PR 列表仍是公开仓库里 `components/workspace/pull-directory.tsx` 的旧 shadcn 拼装。所以这一页看起来像另一个产品，根因在组合，不在 token——token 层本身是干净的（0 处 hex/oklch 字面量、1 处原始调色板类）。

## 决定

- **一个条目只有一层底色、一个目标。** 悬停底色在行上，行内不再嵌第二层底色；点击目标是行本身，行内按钮是它的兄弟，不嵌套。
- **行内操作占位固定、默认为空。** 复选框与「固定」「在 GitHub 打开」共用一个预留槽位，`opacity` 切换，不改变行宽，也不让列表在指针经过时抖一下；`pointer-coarse` 下常显。
- **一行的信息集不随窗口宽度变化。** 条目是一行：仓库标记、`仓库 #编号`、标题（13/20 Medium，主信息）、`+N −M`、时间、状态（12/18，数字 `tabular-nums`）。窄屏只截断标题和仓库名，不隐藏整列。单行 40px，分组表头 32px。
- 2026-11-18 追加（Alex： 「你应该跟他修成一样的才对吧」）：这一页的**信息排列按 Capy**，而 token、字体、颜色仍是 Mikka 的。四处改动：筛选收成一行（搜索、可单独移除的条件标签、分组、⋯）；条目从两行改为单行 40px；详情改成表头（主操作 + 标题 + 状态行）加「概览 / 改动」两个视图，事实是固定标签列的值表；未连接 GitHub 时用列表区里的一个状态块，不再在页面上插一段红字。
- **分组按处理顺序，不按字母或枚举。** `pinned → 失败 → 检查中 → 可合并 → 打开 → 草稿 → 已合并 → 已关闭`（`pullAttentionOrder`）。组内按更新时间倒序。分组表头固定，随列表滚动留在顶部。
- **筛选按使用频率分家。** 三种读取口径（打开 / 可合并 / 已合并 / 全部）常显；状态、作者、标签、分组收进「筛选」弹层，按钮上写已启用的项数；生效的筛选在列表上方以可单独移除的标签出现。
- **每一种状态都画出来。** 骨架与真实行同高；「一个都没有」与「被筛掉了」是两种空状态，各自给一个能解决它的动作（刷新 / 清除筛选）。
- **详情不是列表的复读。** 标题之下是状态、作者、时间一行，事实按「标签 | 值」两列排，描述与关联任务各自成段，段与段之间用 `--rule` 分隔。

## 实现

- 公开仓库：`components/workspace/pull-directory.tsx`（数据、筛选状态、选择、键盘）、`pull-row.tsx`（条目、分组表头、骨架）、`pull-filters.tsx`（筛选条、生效标签、保存的视图）、`pull-preview.tsx`（详情）、`lib/pull-directory.ts`（`pullAttentionOrder`、`SavedPullView`）。
- 没有新增 UI 槽：一页的代码在哪就改在哪（[2026-11-08-2133](2026-11-08-2133-one-ui.md)）。
- 图标：本页沿用公开仓库钉住的 `lucide-react`（`ui-policy.json` 的 `iconLibrary`）；整体迁移到 Hugeicons 由 MIKK-55 负责，本页不预先分裂成两套。PR 状态标记仍由 `PullRequestIcon` 画，全产品同一份。

## 没有做的

- 不复制 Capy 的前端代码。它的安装包只有压缩后的渲染层产物（993 个 chunk，无 source map、无许可），既不可读也不可合法搬运；可读的是它随包的 CSS，本次取的就是那些量出来的值。
- 不改宿主层（`mikka-hosted-ui`）的 token 或付费组件的外观。
