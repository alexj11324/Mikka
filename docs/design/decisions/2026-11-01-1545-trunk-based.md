# Trunk-based merging

- Date: 2026-11-01
- Source: Alex, approved through the coordinator session: replace the
  five-PR integration batches with trunk-based development.
- Rule: — (process, not product)
- Replaces: [2026-11-01-1440-dev-workflow-local-first](2026-11-01-1440-dev-workflow-local-first.md) rule 5 (merge batches through `integration/<date>-<n>`, and pushing small fixes to an integration branch together)

[`docs/dev-workflow.md`](../../dev-workflow.md) § 5 holds the rule:

1. Every PR branches from `main` and changes one thing.
2. When CI is green, the coordinator squash-merges it directly.
3. Changes to auth, signup, privilege or credentials are reviewed first; UI
   changes merge only after their screenshots are reviewed.
4. Each module has an owner, whom anyone else asks before changing it: the
   local development environment and fake services, the local test-mode
   rules, and MVP acceptance.
5. A documentation conflict is resolved by whoever merges, by editing the
   documents directly.

A migration timestamp that lands out of order is renamed by whoever merges
the later PR (1440 rule 6 otherwise stands).
