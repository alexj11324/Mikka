# No new polling; CI rejects it

- Date: 2026-11-05
- Source: Alex, 2026-11-05, on database transfer burning the monthly budget, mostly from periodic polling: 「轮询的问题没有办法根治吗？没有办法由 CI 直接把它处理掉吗？」
- Rule: —
- Replaces: —

No new periodic data polling, on web, mobile, the daemon, workflows or the
server. A screen or process that needs to know data changed uses live push
(`hooks/use-live-key.tsx`, `lib/live/*`; the daemon uses the device gateway).
The existing pollers are replaced one by one in #1212.

Enforced by `scripts/polling-policy.mjs` (`pnpm lint:ui`, `pnpm test:ui-policy`).
It flags a `refreshInterval` or `refetchInterval` that is not `0` or `false`,
`setInterval(`, constants named `*_POLL_MS`, `*POLL_INTERVAL*` or `*_EVERY_MS`,
our polling helpers (mobile `useApi` with an interval, the daemon's
`gate.monitor`, `pollUntil`), and a `while` or `for` loop that awaits a delay
(short retries bounded by 10 or fewer attempts are not polling).

`pollingAllowlist` lists every poller that existed when the guard landed, by
file, with its reason and number of sites. It only shrinks:

- a file not on the list fails, and so does a listed file with more sites;
- a database poll is listed with `tracking: '#1212'` and what replaces it;
  when it is replaced, its entry must be deleted (an entry with no sites fails);
- new entries are allowed only for timers that read no data (`kind: 'ui-timer'`:
  animations, clocks, loaders) and third-party APIs (`kind: 'external'`), each
  with its reason.

Two other kinds describe what was already there: `local` (waits on a file
lock or a process on the same machine) and `keepalive` (the device gateway
WebSocket ping that keeps live push connected).
