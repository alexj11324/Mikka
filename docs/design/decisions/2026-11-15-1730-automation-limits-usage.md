# 自动化：每日上限、用量和自动停用

Alex，2026-11-15：自动化按 Capy 的 Automations 补齐，第二步是每日运行上限、按天用量和自动停用。延续 [2026-11-15-1337](2026-11-15-1337-automations-v1.md) 和 [2026-11-15-1704](2026-11-15-1704-automation-github-triggers.md)。

## 决定

- **每天最多运行**（`maxRunsPerDay`，1 到 500，可不设）：按自动化自己的时区算一天。等待中、运行中和已结束的运行都算，跳过和取消的不算。到上限后，定时和事件触发的运行记为「跳过」（`dailyRunLimit`），立即运行直接拒绝。
- **用量**：编辑页按天显示最近 14 天的运行次数、跳过次数、建出的任务数和花费。花费是它建出的任务（每个任务只算一次，追加到同一个任务的运行也算在内）在托管模型上用掉的钱，记在花费发生那天；用订阅跑的任务不产生这部分花费。和运行结果一样，只有创建者和 owner/admin 能看到花费，其他成员只看到次数。
- **自动停用**：一次运行因为创建者失去权限而失败时（不再是 active 成员、Bot 不可用或已归档、仓库、机器或 Agent 配置不可用），自动化被暂停，并记下原因（`disabled_reason`），列表和编辑页显示出来；等待中的运行一并取消。恢复时重新检查，查过了才清掉原因。人手动暂停不记原因。

实现：`docs/backend/179-conversation-schedules.md` § Limits and usage。
