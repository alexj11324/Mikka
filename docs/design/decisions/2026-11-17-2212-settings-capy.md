# Model settings follow Capy's information hierarchy

Alex asked on 2026-11-17 to inspect Capy Electron's settings implementation and fix Mikka's confusing model settings, then validate and merge the fix.

The examined official installer was Capy Desktop 0.9.2 for Linux x86_64, downloaded from the link on `https://capy.ai/`. This supersedes the older 0.8.0 reference for this task. Inspection of the packaged renderer's `features/settings/model-routing.tsx` shows connections before the model catalogue, connection-specific state, and a separate out-of-usage policy. Packaged gallery images are illustrative fixtures, not a signed-in live Capy account.

Mikka keeps its existing runtime and permission model. Its official Models page presents subscription connections and API keys first, then the canonical per-Agent model order and the API-key fallback setting, then the model catalogue, run location, and Agent profiles. There is no second "Tasks start with" editor that rewrites the same order elsewhere. A filter with no matching models describes that filter, not all account credentials. Loading, failed reads, an existing credential without models, and no credentials are different states.

Keep the installed affectUI parts, CSS and demo unchanged. Product composition uses the existing Mikka binding slots; no Capy implementation or paid UI source is copied into the public repository. The fallback row explicitly names its missing API-key prerequisite without changing the saved policy or silently switching it off.
