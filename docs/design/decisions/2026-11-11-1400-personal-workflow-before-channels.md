# 先完成单人工作流，再推进 Channel

- Date: 2026-11-11
- Source: Alex，Capy 能力对齐任务会话。先提出“Channel 包含 project 和 task，也包含成员”，随后明确纠正执行优先级为先做好单人整个 workflow；本任务协调记录确认 Channel 后置。
- Rule: —（本轮产品范围与交付顺序）
- Replaces: —

本轮先完成一个人的工作闭环：发起任务 → 选择项目环境与工具 → 执行 → 查看同一 Run 的文件与 diff → 继续或重试 → 验收。优先修复阻断这条路径的真实问题，并分别记录各层能够证明的行为。

Channel 保留为后续产品方向：在 Workspace 内围绕主题聚合项目、任务、文件与参与成员。Alex 认可这一概念，不代表实现、设计验收或发布；本轮不实现或发布 Channel，也不因这一概念引入新的组织层或隐式共享权限。已有资源的 Workspace 归属与私有内容边界继续适用。

团队协作、Channel、管理后台与完整 Capy 路由覆盖不作为这轮单人闭环的前置工作。持久 Drive 文件树与执行中的 Coding Workspace 分别验证，前者不能代替后者的 Files/diff 证据。

真实 PostgreSQL 回归、真实 daemon 传输与真实模型订阅执行分别报告。不同 Workspace、不同 Run 或不同测试替身的结果不能合成“个人订阅端到端已通过”。两种官方订阅沿用各自模型与独立验收规则，缺少实际执行证据时记录“无法验证”及缺失条件。

对应的版本、命令与验收边界见[单人工作流验收记录](../../acceptance/personal-workflow-20261111.md)。
