# 自动化：Webhook 地址

2026-11-15：Alex 要求把自动化补齐到 Capy 的程度（「补齐」）。这是第 4 步：每个自动化有自己的 Webhook 地址，可以把一段时间内的请求合成一次运行。延续 [2026-11-15-1704](2026-11-15-1704-automation-github-triggers.md)。

## 决定

- 「满足任一条件就运行」里加 **Webhook**。打开并保存后，可以生成这个自动化自己的地址。向它发 POST 请求就会运行，正文是任意文本或 JSON，最多 64 KB。只用于交给 Bot 的自动化。
- 地址里的密钥是唯一凭证：随机生成，只保存它的 SHA-256，只在生成的那一刻显示一次。重新生成后旧地址立即失效。只有创建者、所有者和管理员能生成；在对话里不能生成，因为地址不能进入模型的上下文。追踪数据里地址中的密钥会被遮住。
- **合并请求**：每个请求单独运行，或者在 1、5、15、60 分钟内收到的请求合成一次运行，在窗口结束时开始。一次最多合并 50 个请求、256 KB，超出的开始下一次。
- 发送方可以带 `Idempotency-Key`（或 `X-Request-Id`）：同一个 ID 只算一次。
- Bot 收到的要求后面附上每个请求，放在 `<webhook_request>` 块里，并说明这是调用地址的人发来的数据，不是创建者的指示。正文不能提前结束这个块。
- 每天最多运行次数和同时运行数照常生效：超出时这个请求记为「已跳过」，正文保存在运行记录里，不发到对话。
- 返回：已排队、已合并、重复或已跳过都是 202；地址不存在或已关闭是 404；自动化暂停时是 409；正文太大是 413；不是文本是 415。
