# Node 22 and 24 across Mikka

Status: accepted. Issue: #2817.

## Decision

Mikka supports the latest Node.js 22.x and Node.js 24.x across the web build
and start, self-hosted server, cloud API entry, Eve, daemon, cloud services and
repository scripts. Runtime checks and package engines require `>=22`, not
exactly 24. Build manifests retain the actual build version and accept any
supported major. Bundled Node code targets `node22`.

This supersedes the cloud-only Node 24 restriction in
[2026-11-06-2000](2026-11-06-2000-local-device-node22.md); its local-device
compatibility decision remains in effect. Compatibility is not a downgrade:
`.node-version`, official images, E2B templates and deployment runtime choices
can remain on 24.

Eve 1.0.0-rc.9 has a frozen pnpm patch widening its package engine from `>=24`
to `>=22`. Its CLI reads that declaration; the workflow serialization runtime
requires the Zstandard API available in current 22.x. The patch does not remove
any runtime feature checks. A successful CLI version check alone is not
acceptance: the actual app/Eve build, runtime and tests must run on 22.

Eve's development host also uses `AsyncDisposableStack` and `SuppressedError`,
which are not globals in Node 22. The same patch imports the pinned
`core-js-pure@3.51.0` implementations locally in that host module; a pnpm
package extension declares Eve's dependency. This preserves asynchronous LIFO
cleanup, ownership transfer and suppressed-error aggregation without mutating
host globals or replacing the production runtime. Regression tests cover those
semantics with both globals absent; isolated HTTP acceptance starts the real
Eve development host on both Node versions.

## Verification

`local-device-node22.yml` is extended, not duplicated: a 22/24 matrix installs,
builds and starts the actual app and packaged Eve, then exercises the existing
daemon/installer tests. The selected core/integration unit suites and isolated
PostgreSQL 17 suites in `ui-policy.yml` also run on both majors. Existing Node 24
protected-check names remain unchanged. Each version has its own installed
dependency cache identity; no native module cache crosses Node versions.

Production image selection and release authority are unchanged.
