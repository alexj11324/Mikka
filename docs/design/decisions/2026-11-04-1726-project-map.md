# Project map: a vertical map tab on the project page

- Date: 2026-11-04
- Source: Alex, reviewing the project map drafts (community feedback from kumaxs). On the open questions: 「可以，做吧」 (tab on the project page, detail order, three lanes on desktop and two on a phone); on direction, after comparing products: 「那就竖向，你把这个 spec 写清楚之后，然后开工作。」
- Rule: R-83 (new)
- Replaces: —

A project gets a 「地图」 tab beside 概览, 活动 and 任务. It draws the
project's route as a vertical timeline: the main line is one vertical lane,
each fork point is a decision on that lane, and every branch opens a lane to
the right of the lane it forked from. Abandoned branches stay on the map in a
muted, dashed style and show where they stopped. Picking a node opens its
detail beside the map (a bottom sheet on a phone), in this order: 任务, 决定,
Artifact, 检查, 对话摘要, 线程.

Nested forks follow `git log --graph`: the chosen option stays in its lane,
each other option takes a new lane, and a finished branch frees its lane for
later branches. Desktop draws at most three lanes and a phone two; deeper
branches fold into one row that opens the branch on its own. Selecting a node
highlights its path from the start.

Vertical was chosen over a horizontal graph because nodes carry text (title,
one-line result, Artifacts, PRs, checks), the detail panel takes the right
side, and the phone needs the same structure. The minimap covers the
whole-shape view a horizontal graph would give.
