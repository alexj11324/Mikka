# 主动推荐（Hark 式 personal agent）

日期 2026-10-27。Alex：「我觉得我们可以把 hark 这一套补齐到我们的产品」。
相关规则：R-20（注意力模型）、R-21（建议卡片）、R-40、R-45/R-46（措辞）、R-70（设置先例）、
R-72（网页分身）。调研来源见文末。

## 1. 要补的是什么

Mikka 现在的注意力模型（#339，照 Comma 做）只处理**进来的消息**：每来一条 Gmail、Slack、
GitHub、Linear 或 Notion 事件，就判断一次要不要告诉人。Hark 和 ChatGPT Pulse 多出来的是
**主动**这一半：没有新消息进来，它也会根据对你的了解，自己去找值得告诉你的事。例如：

- 「取消 你的 Verizon 套餐，赶在 11 月 1 日自动扣款 $52.13 之前」：从账单邮件里提取的截止日期；
- 「点 DoorDash 吗？」：工作日中午，你常点外卖；
- 「去 Chi Le Ma 吃饭？Shadyside 新开的川菜面馆」：你常在 Instacart、Weee 买川菜调料，
  后台又查到你家附近新开了一家；
- 「检查 你的 Cloudflare 隧道里哪些还没装 cloudflared 2026.10.2 安全更新」：你用的工具发了安全公告。

这些卡片不是提示词写出来的，靠的是下面这条流水线。

## 2. 流水线

```
采集 → 提炼成事实 → 用户画像 → 生成候选 → 排序和限量 → 选时机推送 → 点卡片直接开始 → 反馈
```

### 2.1 采集

- 已有：Gmail、GitHub、Notion、Linear、Slack 的 webhook，加上每小时补漏（`lib/suggestions`）。
- 新增：
  - 消费邮件（Instacart、Weee、Amazon、DoorDash、Uber 等的订单和收据）要专门解析出商家、商品、金额和时间；
  - 日历；
  - 位置：默认按 IP 推算到城市；精确位置要用户在手机端（#340）同意后才取，只用于用户打开的功能。
- 原始内容不额外保存，只在提炼时读。

### 2.2 提炼成事实，形成用户画像

每条进来的内容在现有的打分步骤之后，再用一个便宜的模型提炼出零到几条**事实**，写进
`user_facts`。另外每天夜里再做一次合并：把多条零散事实归纳成规律（「8 次川菜调料」→ 兴趣：川菜），
过期的降低可信度，矛盾的以最新为准。

`user_facts`（新表）：

| 字段 | 说明 |
|---|---|
| `id`, `userId` | 归个人账户，不按工作区共享 |
| `kind` | `interest`、`routine`、`place`、`subscription`、`deadline`、`tool`、`person`、`preference` |
| `subject` | 一句话，例如「川菜」「工作日 12:00 前后点外卖」「Verizon 套餐，尾号 0001」 |
| `value` | jsonb：金额、日期、时间窗、地点、商家等结构化信息 |
| `evidence` | 来源引用（suggestion id、邮件 id、日期），不存原文 |
| `confidence` | 0–1 |
| `firstSeenAt`, `lastSeenAt`, `expiresAt` | 例如订阅的扣款日之后过期 |
| `state` | `active`、`dismissed`（用户说不对）、`deleted`（用户在「记忆」里删掉，保留记录以免再学到）、`expired`（过了日期或可信度降到很低；再次看到会恢复） |
| `userEdited` | 用户在「记忆」里改过的，以用户为准，模型不再覆盖 |

「记忆」设置页（R-70，先例 ChatGPT 的记忆摘要）把这些事实写成 Markdown 摘要给人看，
可以提问、修改、删除；关掉「记忆」就不提炼、也不用画像做推荐。

### 2.3 生成候选卡片

每个用户每天夜里跑一次**后台调研**，时间在本地 05:00 左右，赶在 08:00 简报之前。由 Cloudflare
Worker 定时触发，和简报共用一套 cron（`docs/suggestions-cron.md`）。有四类来源：

1. **截止日期**：从 `deadline` 和 `subscription` 事实里，挑出未来 7 天内的续费、到期、自动扣款、退货期限。
2. **习惯时间窗**：从 `routine` 事实里得出「工作日 11:45 左右可能要点午饭」这类时间窗，
   存成当天的即时触发（见 2.5），不在夜里推。
3. **兴趣 × 外面的新信息**：每天最多选 3 个高可信度的兴趣，结合 `place`，交给网页分身（R-72，#342）
   或搜索接口去查新店、新活动、降价、新版本。只保留查到的、确实是新的结果，并且要带来源链接。
4. **关注你用的东西**：从 `tool` 事实（你连接的 GitHub 仓库依赖、用到的服务）里查安全公告、
   停服通知和涨价通知。

每个候选都写成一张 R-21 卡片：一句话，动词开头，原因或截止时间写在句子里，带来源；
并附上点击后交给 orchestrator 的完整指令（账号、出处、要做什么、不可逆操作前先停下确认）。

### 2.4 排序和限量

- 候选进入现有的注意力模型（R-20）定级：截止日期类按代价和到期时间定级；兴趣类一律 `normal`，
  进「建议」，不单独打扰人。
- 同级之内的排序分 = 紧急程度 + 价值 + 新鲜度 + 可信度 − 打扰成本 − 同类近期被划掉的次数。
- **每天新的主动卡片最多 5 张**，宁缺毋滥。拿不准就不出（Dot 的教训：推得差，用户会连好的也一起忽略）。
- 和已有的建议、近 14 天推过的卡片去重。

### 2.5 选时机

- **夜间批量**：截止日期、兴趣、关注三类进「建议」，并进 08:00 简报（R-20）。
- **即时触发**：习惯时间窗到了（例如 11:45），或者手机报告的位置命中（例如到了某个商场），
  就由 Coordinator 在它的聊天里发一张卡片，并推送到手机。这类卡片同样算在 R-20 每天 5 次、
  间隔 30 分钟的打扰预算里，也只有 Coordinator 能发。
- 用户正在用电脑时，按 R-20 现有的设置决定手机是否也推。

### 2.6 点卡片直接开始

按 R-21：点卡片后，任务直接交给 orchestrator，网页任务由分身做（#342），需要登录时走密码箱（#180）。
下单、付款、取消订阅这类不可逆操作，执行前必须先确认。

### 2.7 反馈

- 记录每张卡片的结果：点了、划掉、过期没理、点了之后又停下。新表 `suggestion_feedback`，
  或者在 `suggestions` 上加字段。
- 划掉一次：同一事实的可信度下降，同类兴趣 14 天内不再推。
- 连续三次划掉同一类：这个事实标记为 `dismissed`。
- 点了并且完成：可信度上升。
- 划掉时可以选「不感兴趣」或「这不对」两个按钮，只用作反馈，不额外写说明（R-40）。

## 3. 成本

主要开销在提炼（每条消息一次便宜调用）和夜间后台调研（每人每天最多 3 个兴趣查询，再加上关注类查询）。

### 开关（Alex 2026-10-27：「要做个开关吧，做一个 flag」）

主动推荐分成两部分，各有一个开关，因为两部分的成本差得很远：

- **画像**（提炼事实）：每条消息一次便宜调用，成本低。
- **后台调研**（夜间调研、外部搜索、网页分身）：成本高。

开关分四层，从外到内，任何一层是关，这一部分就不跑：

1. **部署级总开关**（环境变量）：
   - `PROACTIVE_PROFILE_ENABLED`：控制画像；
   - `PROACTIVE_RESEARCH_ENABLED`：控制后台调研。

   自己部署的开源版本两个都默认关，不配就完全不花这部分钱。我们的云服务按需打开。
2. **谁能用**（名单或套餐）：`proactive_entitlements`，或者复用将来的套餐表，记录每个用户能用哪一部分以及每日上限。
   第一阶段只开给内部用户，后台调研以后可以做成付费功能。
3. **用户自己的开关**：设置里「记忆」关掉，画像和后台调研都停；单独关掉「主动推荐」，只停后台调研，画像照常给 Coordinator 用。
4. **每人每日预算**：调用次数、搜索次数、分身运行分钟数都设上限，超出就跳过当天，第二天再跑。
   每次运行都记录用量，方便算出每个用户的真实成本。

先给内部用户开，量出真实成本再定套餐。ChatGPT Pulse 一开始也只给 Pro 用户，就是因为算力贵。

## 4. 隐私

- 画像按个人账户隔离，同一工作区的队友看不到彼此的画像。
- 用户能看到、改、删每一条事实，也能整体关掉。
- 精确位置要手机端明确授权，默认关闭。
- 不接受商家返佣，推荐里不夹带广告。Hark 有返佣，可能影响中立，我们不这样做。
- 后台调研只把兴趣关键词和大致地点交给搜索，不把邮件原文发出去。

## 5. 分期

1. **画像**：在现有打分步骤之后加一步提炼，建 `user_facts` 表，夜间合并，接到「记忆」页。
   这是地基，可以马上开工。
2. **夜间后台调研**：截止日期类和关注类先做（不依赖外部搜索之外的东西），再接兴趣 × 外部新信息
   （依赖 #342 的分身或搜索接口）。
3. **排序、限量和反馈**：加 `suggestion_feedback`，卡片上加「不感兴趣」「这不对」，并用于调整可信度。
4. **即时触发**：习惯时间窗加手机位置，依赖 #340。

## 6. 待定

- 提炼和调研用哪个模型，以及每人每天的预算数字。
