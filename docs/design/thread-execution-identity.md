# Thread execution identity

Issue #1163 requires the person to trace an execution's authority and billing. The existing Thread header has a read-only identity button. Its dialog uses the existing owner-only `GET /api/runs/:runId/evidence`; it adds no authorization or diagnostic endpoint.

The dialog shows people, workspace, machines and account labels by name. Raw run, workspace, account and resource IDs are included in Copy diagnostics. Its Agent, model, credential type and subscription route come from that run's frozen definition. The identity snapshot names requester, Bot owner, execution principal, output owner, resource holder and access source, and the model/runtime payer separately. Resource references contain no credentials or connection URLs. `provider_unknown` is shown as unknown external cost; it is never zero. A missing legacy snapshot remains missing and is never filled from current Bot or Settings choices.

The current Thread's displayed run is the target, including a resumed run. Changing that ID remounts the dialog, clears prior display state and closes it. Data is loaded only on open; the cache key includes the exact run ID, retains no prior-key data and does not retry failures automatically. Both response parsing and display selection bind the response ID to the selected run. The normal owner endpoint remains the permission boundary.

The dialog reuses the existing Dialog, Button, Tooltip, Agent/model labels and neutral tokens, with no visible subtitle. It scrolls within the viewport on narrow screens. Its loading, retry, missing-snapshot and unknown-cost states have English and Chinese copy. The run owner sees the entry; a teammate's Thread exposes no new owner-only record. Production-build screenshots in cloud Linux and normal API readback verify this UI under [acceptance.md](../acceptance.md). The accepted presentation is in [thread-run-location.md](thread-run-location.md#part-3--execution-identity-dialog). Production follow-through uses the scope in `AGENTS.md`.
