# Epic 草稿：代码审阅页

> 已不再使用：不另开 Epic。验收标准已并入 #1720 的 #1722（后端）和 #1732（前端），iOS 部分是 #1720 下的新子 issue。保留本文件作为记录。

## 目标

代码任务改完以后，用户从任何能看到这个任务的地方点一次「审阅」，就进入一个整页的审阅页。在审阅页里看改动、写行内评论、发给 Agent、看检查、要求修改或批准合并，不用跳到 GitHub。

做法参照 Linear Diffs：
- 任务上不嵌 diff，只有一行摘要。
- 审阅页默认显示整个 PR 的最终改动。
- 没有仓库文件树。

## P0

### P0-1 一行摘要和「审阅」入口（R0、R0b）

- 聊天里的任务卡片、右栏任务面板、窗口栏「等待你」列表，都显示一行「PR #N · 3 个文件 +42 −7 · ⚠ 1 项检查失败」和「审阅」按钮。
- 非代码任务不显示这一行。
- ⌘⇧B 打开当前任务的审阅页；⌘K 能搜到「审阅 #N」。
- 任务的「活动」里按时间列出每次尝试。尝试不作为 diff 的范围。

验收：
- [ ] 从首屏点 1 次就能进审阅页，任务卡片、等待你列表、任务面板三个入口都通。
- [ ] ⌘⇧B 和 ⌘K「审阅 1471」都能打开审阅页。
- [ ] 摘要里的数字和 PR 的实际改动、检查状态一致，变化时通过实时推送更新，不加轮询（`scripts/polling-policy.mjs` 通过）。

### P0-2 审阅页（R1、R1b）

- 左：任务的对话，含已发送的「你：N 条评论」和回复框。
- 中：只列改动的文件，按文件夹分组，带 +/−，可以标记已看。
- 右：diff，单栏或并排，可以写行内评论。
- 顶栏：
  - 左边是标题和 PR 号；
  - 右边依次是检查摘要（点开就地展开：失败日志摘要、查看完整日志、附到评论）、「要求修改」、「批准合并」、✕。
- 底部：批次条「N 条评论 · 失败检查 · 发给 Agent」。
- 「批准合并」用中性深色按钮，「发给 Agent」用强调色，两者在视觉上明显不同。
- 默认显示整个 PR 的最终 diff（base…head），没有按尝试切换。
- Esc（不在输入框里时）或 ✕ 关闭；切换瞬间完成（R-37）。

验收：
- [ ] 打开后显示 PR 的最终 diff，文件列表只含改动的文件。
- [ ] 给两行写评论，再从检查展开里附上一个失败检查，点「发给 Agent」：任务对话里出现一条「你：2 条评论」，带两处 `文件:行` 引用和检查名；Agent 开始下一次尝试，结果回到同一个对话，审阅页刷新。
- [ ] 「要求修改」和「批准合并」对 GitHub 生效，状态回到审阅页。
- [ ] 刷新页面后，未发送的评论还在。
- [ ] 队友只读：看不到「发给 Agent」「要求修改」「批准合并」，也不能写评论。
- [ ] 两条订阅路径各跑一次真实任务：Claude Code 用 `claude-haiku-5-5`，Codex 用 `gpt-6-luna`。

### P0-3 改动始终可用

- 机器运行中，读机器上的工作区；机器回收后，依次退回检查点的 diff、PR 的 diff。
- 有 PR 以后，改动仍在 Mikka 里显示；「在 GitHub 打开」只是次要链接。
- 大改动按文件加载，不再整块提示「太大」。

验收：
- [ ] 运行中、已结束（有检查点）、已开 PR 三种状态都能打开审阅页，内容与 git 一致。
- [ ] 超过 8 MiB 的改动能按文件打开。

### P0-4 iPhone 同样能审阅（R2、R3）

- 聊天任务卡片的摘要行，点一次进审阅页。
- 审阅页有：检查摘要（点开展开）、PR、要求修改 / 批准合并、改动文件列表。
- 文件 diff 页可以写行内评论；悬浮条「N 条评论 · 发给 Agent」。

验收：
- [ ] TestFlight 上完成 P0-2 的评论和发送流程，消息在 Web 端也看得到。
- [ ] 在 iPhone 上「批准合并」后，Web 端的状态同步。

## P1

- **按提交筛选：** 放在 diff 的表头，默认收起。
  - 验收：选中一个提交后只显示它的改动。
- **撤销文件或块：** 在审阅页撤销某个文件或某一块改动。
  - 验收：撤销的结果在 git 里可见，对话里有一条记录。

## P2（可选）

- 仓库文件树和只读源码。
- 终端：只有任务负责人能操作，队友只读，不显示密钥文件。
- 开发服务器预览。
- 把代码还原到某一轮。

## 不做

- 任务面板和聊天卡片里不嵌 diff。
- 不加「对话 · 改动 · 文件 · 验收 · 预览」这组标签。
- 不按尝试切换 diff。
