# Coding Workspace 迁移前后历史核验说明

本文件是 #1782 创建的迁移前验收夹具，记录可复用的历史核验流程。实际执行结果由对应验收回执记录。

## 迁移前

1. 使用正常账户接口确认 Workspace 成员资格，并逐个确认所选 Task 的读取权限。
2. 固定一组 Task UUID。集合须包含真实已发布的 PR 回执和已经结束的旧 Run；两类历史可以由不同 Task 提供。
3. 在只读、可重复读事务中保存既有 Task 编号、发布编号与分支、Run 冻结配置的摘要，以及原始行 ID。
4. 记录应用版本、采集来源、证据摘要与事务回滚、连接关闭和会话退出结果。

## 迁移后

1. 使用同一组 Task UUID 重新确认当前权限，并按迁移前保存的行 ID 读取历史。
2. 比较既有编号、发布关系和冻结配置摘要。正常业务新增的行单独记录。
3. 若迁移前没有 Project 执行快照，将该类旧快照兼容性记为不适用。
4. 保留失败回执；任何缺行、摘要变化或清理失败都须定位后重跑。

## 夹具清理

完成同一批历史的前后比较后，结束本夹具的计算资源、关闭本夹具 PR，并精确清理对应 Task 分支与测试 Task。历史记录通过产品正常保留策略留存。
