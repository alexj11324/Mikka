# Mikka development

- Before any design, spec or UI work, read `docs/design/README.md`. It sets which source wins and points to the rules, component list, decision log and spec template. Run `docs/review-checklist.md` before showing UI to anyone; new decisions from Alex go into `docs/design/decisions.md` the same day.
- Bot, thread and chat mean what `docs/design/glossary.md` says. The left column is the bot list (bots chat with people and dispatch tasks); the right column is the thread list (threads do the work, each with its own name). There is no conversation list.
- Develop and accept changes on cloud Preview deployments. Do not start a development server, database, browser acceptance environment, build or `tsgo` on the developer's Mac. Run builds and type checks in remote CI; use deployed previews for runtime checks. Small source-only unit tests may run without a server.
- Test in layers (CONTRIBUTING.md, "How changes are tested"): while working run lint and the unit tests for what you changed, typecheck in an agent container or remote CI, plus the one browser test for a flow you changed. Do not run the full Playwright suite for every step; CI runs it when a pull request is ready for review, before it merges into main.
- Store project credentials in the Mikka Infisical Cloud project. Use cloud Secret Syncs and workload identities for delivery and Agent access. Never commit secret values or add credentials to local environment files.
- Before asking for Infisical or database access, identify the environment, resource and effective identity, then check the existing authorized path and the actual error. A successful path for the requested action does not need a second permission request. On the developer's Mac, follow `~/.codex/rules/infisical-api.md` when available; cloud tasks use their own configured workload identity and must not assume access to the Mac's Keychain.
- Google and GitHub sign-in use the stable HTTPS OAuth proxy hub configured by `BETTER_AUTH_OAUTH_PROXY_URL`. Give trusted previews the dedicated shared proxy secret through cloud configuration. Each preview uses its own exact runtime origin; changing v0 hosts do not require shared-domain wildcards.
- Preserve environment and Neon branch boundaries. Preview application data must use the matching cloud database with the required schema. Verify the deployed path after changing credentials or callbacks.
- Running an authorized test includes its normal setup and cleanup of disposable fixtures, schemas and temporary files created by that test in an isolated test environment. Verify the target and isolation first; do not extend this to shared or production data. Honor any explicit preservation or approval requirement for the current task.
- Preserve unrelated changes and keep secret values out of terminal output, screenshots and reports.
- Follow `docs/acceptance.md` for runtime acceptance. Use direct Google/GitHub OAuth and reuse authorized browser sessions; do not require the user to enter a Mikka password for routine acceptance. Diagnose account-linking conflicts separately without weakening account ownership checks.
- Hand off the Agent's branch, commit SHA and unique Preview deployment URL. Keep that version fixed during acceptance; v0 `Latest`, moving branch aliases and the shared production domain cannot identify a frozen Agent delivery.
